## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Combined Task 1 and Task 2 commits into one**
- **Found during:** Attempting to commit Task 1 (`handleStartCareer` + mount guard) standalone, before appending Task 2's handlers
- **Issue:** `tsconfig.app.json` has `noUnusedLocals: true`. A Task-1-only version of the file declares `const [pendingCareerLeagueFixture, setPendingCareerLeagueFixture] = useState(...)` per the plan's own Task 1 action text, but `setPendingCareerLeagueFixture` is only consumed by Task 2's `handlePlayCareerLeagueMatch` — so the Task-1-only intermediate file fails `npx tsc -b --noEmit` (the plan's own per-task `<verify>` command) with `TS6133: 'setPendingCareerLeagueFixture' is declared but its value is never read`.
- **Fix:** Committed the full file (Task 1 + Task 2's handlers) as a single commit, keeping every commit on the branch typecheck-clean, rather than force an artificially broken intermediate state to preserve two smaller commits.
- **Files modified:** `src/hooks/useCareerManager.ts`
- **Verification:** `npx tsc -b --noEmit` shows zero errors attributable to `useCareerManager.ts` at every commit on the branch.
- **Committed in:** `f03da43`

**2. [Rule 3 - Blocking] In-memory localStorage polyfill for the jsdom test environment**
- **Found during:** Task 3, first run of `useCareerManager.test.ts`
- **Issue:** `localStorage.clear()` and `useCareerManager`'s internal `usePersistedState`/`localStorage` calls threw/no-opped under `// @vitest-environment jsdom` in this repo's Node 26 + vitest 3.2.6 + jsdom 29.1.1 stack. Root cause: Node 22+ defines a built-in global `localStorage` getter (returns `undefined` and emits `ExperimentalWarning: localStorage is not available because --localstorage-file was not provided` unless a CLI flag is passed). Vitest's bundled jsdom environment provider only copies a `window` key onto the test global if that key is either absent from the Node global or present in its own `KEYS` allowlist — `localStorage` is in neither list, so Node's non-functional global wins and jsdom's working `window.localStorage` is never surfaced. This affects every jsdom test in the repo that touches `localStorage`, but no prior test exercised this path.
- **Fix:** Added a small self-contained in-memory `Storage` polyfill (`MemoryStorage` class) at the top of `useCareerManager.test.ts`, installed via `Object.defineProperty(globalThis, 'localStorage', { value: new MemoryStorage(), configurable: true, writable: true })`. Scoped to this test file only — deliberately did NOT touch the shared `src/test-setup.ts` to avoid any merge risk with the sibling parallel agent (04.4-05) also executing in this wave.
- **Files modified:** `src/hooks/__tests__/useCareerManager.test.ts`
- **Verification:** All 3 tests in the file pass; full suite (`npm run test`) — 178/178 tests pass across 20 files.
- **Committed in:** `0b6131b`
