**Three new prop-driven career-mode screens — CareerHubScreen (manager identity/reputation/history/navigation with a visible D-13 season-advance gate), TradeProposalScreen (opponent+player trade picker reusing TournamentSetupScreen's global classes), SeasonEndScreen (season transition summary echoing LeagueScreen's champion visuals) — none wired into App.tsx yet.**

## Accomplishments
- CareerHubScreen renders manager name/reputation, a live season summary card (league name, current year, computed league position via `computeStandings`, cup stage, trades used), navigation into league/cup/trade flows, a literal `state.season.league.phase === 'done' && state.season.cup.stage === 'champion'` gate on the "Avançar Temporada" button (D-13), and reversed-chronological history with sign-colored reputation deltas.
- TradeProposalScreen implements the full opponent-team → own-player → opponent-player → confirm flow using only existing global App.css classes (`team-grid`, `team-tile`, `select-summary`, `select-slot`, `slot-nav-btn-primary`) — no new CSS module. Blocks the picker UI entirely when `tradesRemaining <= 0`. Calls `onPropose(offeredPlayerId, opponentId, requestedPlayerId)` with the exact argument order 04.4-06 needs.
- SeasonEndScreen renders every `CareerSeasonHistoryEntry` field plus `newReputation`, with a champion block visually matching `LeagueScreen`'s crown/crest/colored-name pattern (guarded for a not-found champion team) and a CTA into the next season year.

## Decisions Made
- Used the `league` prop in `CareerHubScreen` (league name + `cupName` label) rather than leaving it unused, since the plan's literal interface requires it as a prop but the original task description didn't explicitly spell out a render use for it beyond `computeStandings` (which reads from `state.season.league`, not the `league` prop). This keeps the component free of unused-variable errors while adding real value (league branding on the hub).
- `SeasonEndScreen` resolves the champion team directly from the `league` prop (`league.teams.find(...)`) rather than importing `getLeague` from `data/leagues/index.ts`, since the prop already carries the exact `LeagueDefinition` per the `<interfaces>` contract — no extra lookup indirection needed.
