# Phase 4.2: Data-Driven Leagues - Context

**Gathered:** 2026-06-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Substituir Premier League hardcoded em `data/premierLeague.ts` por um sistema data-driven que suporta múltiplas ligas. Cada liga define seus times, número de rodadas, regras específicas (Champions League, rebaixamento) e comportamento da CPU.

Já existe trabalho iniciado: `src/data/leagues/` com 4 ligas (Premier, La Liga, Bundesliga, Serie A), `LeagueSelectScreen.tsx`, tipos em `types.ts` e gerador em `generateTeam.ts`.
</domain>

<decisions>
## Implementation Decisions

### Estrutura de dados
- **D-01:** Uma liga por arquivo em `src/data/leagues/` — premierLeague.ts, laLiga.ts, bundesliga.ts, serieA.ts
- **D-02:** Arquivo `index.ts` exporta `allLeagues: LeagueDefinition[]`
- **D-03:** `LeagueDefinition` type define: id, name, country, flag, totalRounds, teams, rules (European slots, regulation), cpuProfile

### Fluxo de seleção
- **D-04:** Nova tela `LeagueSelectScreen` antes de HomeScreen no fluxo
- **D-05:** Fluxo: LeagueSelect → Home → TournamentSetup/TeamSelect
- **D-06:** Componente já criado (`src/components/LeagueSelectScreen.tsx`) — reutilizar

### Regras por liga
- **D-07:** Número de rodadas variável por liga (38 PL, 34 Bundesliga, 38 La Liga, 38 Serie A)
- **D-08:** Slots europeus: Champions League (top 4), Europa League (5º + Copa), Conference (6º) — visuais na tabela
- **D-09:** Rebaixamento: últimos 3 caem — visual na tabela (zona de rebaixamento)

### Salvamento
- **D-10:** Saves separados por liga: `fp:leagueState:{leagueId}`
- **D-11:** Trocar de liga mantém progresso de cada uma independentemente
- **D-12:** Premier League existente mantém compatibilidade (`fp:leagueState` migra para `fp:leagueState:pl`)

### Comportamento da CPU
- **D-13:** CPU tactics variam por liga:
  - Serie A: mais defensiva (-10% pressing, +5% defensive line)
  - Bundesliga: mais ataque (+10% pressing, +5% tempo)
  - Premier League: balanceado (default atual)
  - La Liga: mais posse (-5% pressing, +5% passing focus)

### Claude's Discretion
- Migração do save atual da Premier League para o novo formato com namespace
- Refatoração do `useLeagueManager` para aceitar `leagueId` como parâmetro
- `generateTeam.ts` já existe no WIP — revisar e padronizar interface
- Formato da tabela de classificação com indicadores visuais (CL, EL, rebaixamento)
- Detalhes de implementação do `cpuProfile` no engine de tournament
</decisions>

## Existing Code Insights

### Reusable Assets
- `LeagueSelectScreen.tsx` — grid de cards com flag, nome, país, nº rodadas. Usa CSS Modules. Pronto para integrar.
- `data/leagues/index.ts` — já exporta `allLeagues` e `getLeagueById`
- `data/leagues/types.ts` — `LeagueDefinition`, `ClubDefinition`, `LeagueRules`, `CpuProfile` types
- `useLeagueManager` — hook existente a ser estendido com parâmetro `leagueId`

### Established Patterns
- Hooks recebem dependências via params object (padrão Phase 4.1)
- CSS Modules para estilos scoped
- `usePersistedState` com chave `fp:` para localStorage
- Engine usa funções puras — ideal para `cpuProfile` como parâmetro de simulação

### Integration Points
- App.tsx: adicionar screen 'league-select', rotear antes de 'home'
- useLeagueManager: adicionar `leagueId` param, carregar dados via `getLeagueById`
- tournament.ts: `generateLeagueSchedule` já aceita `teams: Team[]` — totalRounds deve vir de `LeagueDefinition.totalRounds`
- Premier League legada (`data/premierLeague.ts`) — manter como fallback ou migrar completamente
</code_context>

<specifics>
## Specific Ideas

- Rebaixamento e slots europeus são **visuais** na tabela de classificação — não simulam competições separadas
- Cores na tabela: verde = Champions, azul = Europa, laranja = Conference, vermelho = rebaixamento
- `cpuProfile` é um objeto no `LeagueDefinition` com multiplicadores: `pressingMod`, `defensiveLineMod`, `tempoMod`, `passingFocusMod`
- Migração de save: na primeira execução pós-update, detectar `fp:leagueState` legado e mover para `fp:leagueState:pl`
</specifics>
